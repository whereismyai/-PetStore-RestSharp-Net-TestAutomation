# BUG-005: DELETE /pet/{id} of a missing pet returns 404 with an empty body

- Id: BUG-005
- Status: Open
- Title: DELETE /pet/{id} of a missing pet returns 404 with an empty body
- Raised: 2026-11-15
- Endpoint: DELETE /pet/{petId}
- Environment: https://petstore.swagger.io/v2
- Linked test: `Deleting a pet that does not exist is answered with Pet not found` (`@bug:BUG-005`, PetStore_Pet.feature)

## Description

The spec defines `404 Pet not found` for `DELETE /pet/{petId}`, as it does for `GET /pet/{petId}`. `GET` of a
missing pet answers with that message; `DELETE` of a missing pet answers `404` with an empty body.

## Steps to reproduce

1. `DELETE /pet/918273999` (an Id that does not exist)
2. `GET /pet/918273999`

## Expected

- Step 1 returns `404` with message `Pet not found`, like step 2.

## Actual

- Step 1 returns `404` with an empty body.
- Step 2 returns `404` with `{"code":1,"type":"error","message":"Pet not found"}`.

## Impact

Low: the status code is right, but clients that read the error message get nothing for `DELETE`, and the two
endpoints report the same error differently.

# BUG-005: DELETE /pet/{id} of a missing pet returns 404 with an empty body

- Id: BUG-005
- Status: Closed
- Resolution: Not a bug
- Title: DELETE /pet/{id} of a missing pet returns 404 with an empty body
- Raised: 2026-11-15
- Closed: 2026-11-16
- Endpoint: DELETE /pet/{petId}
- Environment: https://petstore.swagger.io/v2
- Linked test: none (the scenario was removed when the bug was closed)

## Description

`DELETE` of a missing pet answers `404` with an empty body, while `GET` of a missing pet answers `404` with
`{"code":1,"type":"error","message":"Pet not found"}`.

## Steps to reproduce

1. `DELETE /pet/918273999` (an Id that does not exist)
2. `GET /pet/918273999`

## Actual

- Step 1 returns `404` with an empty body.
- Step 2 returns `404` with `{"code":1,"type":"error","message":"Pet not found"}`.

## Resolution: Not a bug

The report expected step 1 to return the message `Pet not found`, like step 2. The contract does not support
that expectation:

- In `swagger.json`, the `404` response of `DELETE /pet/{petId}` has only `description: "Pet not found"` and
  no `schema`.
- [OpenAPI 2.0, Response Object](https://spec.openapis.org/oas/v2.0.html#response-object): "If this field
  [schema] does not exist, it means no content is returned as part of the response."
- A `description` documents the response for people; it is not a required value of a JSON `message` field.

The status code, `404`, matches the contract. It is checked for a pet that was already deleted in `A deleted pet
cannot be deleted again, and its Id can be used for a new pet`. The different bodies of `GET` and `DELETE` are an inconsistency worth a note to the API
owners, not a defect against the contract.

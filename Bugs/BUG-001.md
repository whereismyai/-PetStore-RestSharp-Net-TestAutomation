# BUG-001: POST /pet with an existing Id silently overwrites the existing pet

- Id: BUG-001
- Status: Open
- Title: POST /pet with an existing Id silently overwrites the existing pet
- Raised: 2026-11-14
- Endpoint: POST /pet
- Environment: https://petstore.swagger.io/v2
- Linked test: `Creating a pet with an existing Id is rejected with 409 Conflict and keeps the existing pet` (`@bug:BUG-001`, PetStore_Pet_Lifecycle.feature)

## Description

Creating a pet with an Id that already belongs to another pet is not rejected. The API answers `200`
and replaces the existing pet with the new data (upsert), so the original pet is lost without any error.

## Steps to reproduce

1. `POST /pet` with body `{"id": 770001, "name": "First", "status": "available", "photoUrls": ["https://example.com/pet.jpg"]}` -> `200`
2. `POST /pet` with body `{"id": 770001, "name": "Second", "status": "sold", "photoUrls": ["https://example.com/pet.jpg"]}`
3. `GET /pet/770001`

## Expected (assumption, to be agreed with the API owners)

- Step 2 is rejected with `409 Conflict`.
- Step 3 returns the original pet: `name = First`, `status = available`.

Neither point comes from the contract. `swagger.json` defines only `405 Invalid input` for `POST /pet`: it
gives no code for a duplicate Id and does not say whether `POST` may replace an existing pet. Both are
assumptions:

- `409 Conflict` is the usual HTTP answer to a create that clashes with an existing resource.
- "Create must not overwrite" follows from `PUT /pet` being the documented update operation, which is an
  argument, not a rule in the spec.

The bug stays `Open` because silent data loss is a real risk for clients either way. If the owners confirm
that `POST` is an upsert by design, close it with `Resolution: Works as designed` and remove both linked
scenarios.

## Actual

- Step 2 returns `200` with `{"id":770001,"name":"Second","photoUrls":["https://example.com/pet.jpg"],"tags":[],"status":"sold"}` (rechecked 2026-11-15).
- Step 3 returns `200` with the overwritten pet: `name = Second`, `status = sold`.

## Impact

Any client that creates pets with explicit Ids can destroy existing data without noticing.
While this bug is `Open`, the linked scenarios are skipped by the `BugHooks` before-scenario hook.
Set `Status: Fixed` (or `Closed`) once the API is fixed - the scenarios run again automatically.

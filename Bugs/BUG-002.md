# BUG-002: POST /pet without an Id gives every pet the same generated Id

- Id: BUG-002
- Status: Opened
- Title: POST /pet without an Id gives every pet the same generated Id
- Raised: 2026-11-14
- Endpoint: POST /pet
- Environment: https://petstore.swagger.io/v2
- Linked test: `Pets created without an Id or with Id 0 get their own generated Ids` (`@bug:BUG-002`, PetStore_Pet.feature)

## Description

A pet created without an Id (field missing or `null`) gets the Id `9223372036854775807` (the largest int64)
every time. Each such pet therefore replaces the previous one: only the last pet created without an Id exists.

## Steps to reproduce

1. `POST /pet` with body `{"name": "Toothless", "category": {"name": "DRAGONS"}, "photoUrls": ["https://example.com/pet.jpg"]}`
2. `POST /pet` with body `{"id": null, "name": "Toothless", "category": {"name": "NIGHT_FURY"}, "photoUrls": ["https://example.com/pet.jpg"]}`
3. `GET /pet/9223372036854775807`

## Expected

- Steps 1 and 2 return two different generated Ids.
- Each pet can be read back by its own Id with its own category.

## Actual

- Steps 1 and 2 both return `"id": 9223372036854775807`.
- Step 3 returns the second pet (`NIGHT_FURY`); the first pet is gone.

Observed on 2026-11-13 and 2026-11-14.

## Retest (2026-11-15)

Does not reproduce any more, so closed as Cannot reproduce: nothing shows that the server was fixed. Steps 1 and 2
now return different Ids (`9223372036854022629`, `9223372036854022630`).

The likely cause is still there. A generated Id is the highest existing Id + 1:

- an Id freed by `DELETE` goes to the next pet (`9223372016900018801` was deleted, and the next pet got it);
- an Id sent as `0` or negative is replaced by a generated Id, like a missing one;
- generated Ids are already close to the int64 maximum (`9223372036854022631`, 753 176 below it).

Once any user stores a pet at the int64 maximum, the next generated Id would overflow, which matches the
symptom above. Reopen (`Status: Open`) if it reproduces.

## Impact

Clients that rely on server-generated Ids silently overwrite each other's data. Deleting "your" pet
deletes whatever pet currently holds that Id.

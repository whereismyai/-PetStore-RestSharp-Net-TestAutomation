# BUG-004: GET and DELETE /pet/{id} with an invalid Id return 404 and a Java exception

- Id: BUG-004
- Status: Open
- Title: GET and DELETE /pet/{id} with an invalid Id return 404 and a Java exception
- Raised: 2026-11-14
- Updated: 2026-11-15 (DELETE and Ids beyond int64 added)
- Endpoints: GET /pet/{petId}, DELETE /pet/{petId}
- Environment: https://petstore.swagger.io/v2
- Linked tests: `Getting a pet by an invalid ID is rejected with 400 Invalid ID supplied` and `Deleting a pet by an invalid ID is rejected with 400 Invalid ID supplied` (`@bug:BUG-004`, PetStore_Pet.feature)

## Description

The spec defines `400 Invalid ID supplied` for `GET /pet/{petId}` and `DELETE /pet/{petId}`. An Id that is not
an int64 (non-numeric, or beyond the int64 maximum) is answered with `404` instead, and the message exposes the
server's internal exception.

## Steps to reproduce

1. `GET /pet/abc`
2. `GET /pet/9223372036854775808` (int64 maximum + 1)
3. `DELETE /pet/abc`
4. `DELETE /pet/9223372036854775808`

## Expected

- `400` with message `Invalid ID supplied` for each request.

## Actual

- Each request returns `404` with `{"code":404,"type":"unknown","message":"java.lang.NumberFormatException: For input string: \"<id>\""}`,
  e.g. `For input string: \"abc\"`.

## Impact

Clients cannot tell a malformed request from a missing pet, and internal implementation details leak
in the error message.

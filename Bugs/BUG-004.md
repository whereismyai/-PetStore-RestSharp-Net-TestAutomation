# BUG-004: GET /pet/{id} with a non-numeric Id returns 404 and a Java exception

- Id: BUG-004
- Status: Open
- Title: GET /pet/{id} with a non-numeric Id returns 404 and a Java exception
- Raised: 2026-11-14
- Endpoint: GET /pet/{petId}
- Environment: https://petstore.swagger.io/v2
- Linked test: `Getting a pet by a non-numeric ID is rejected as an invalid ID` (`@bug:BUG-004`, PetStore_Pet.feature)

## Description

The spec defines `400 Invalid ID supplied` for `GET /pet/{petId}`. A non-numeric Id is answered with `404`
instead, and the message exposes the server's internal exception.

## Steps to reproduce

1. `GET /pet/abc`

## Expected

- `400` with message `Invalid ID supplied`.

## Actual

- `404` with `{"code":404,"type":"unknown","message":"java.lang.NumberFormatException: For input string: \"abc\""}`.

## Impact

Clients cannot tell a malformed request from a missing pet, and internal implementation details leak
in the error message.

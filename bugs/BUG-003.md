# BUG-003: POST /pet accepts and stores invalid pets

- Id: BUG-003
- Status: Open
- Title: POST /pet accepts and stores invalid pets
- Raised: 2026-11-14
- Endpoint: POST /pet
- Environment: https://petstore.swagger.io/v2
- Linked test: `An invalid pet is rejected and nothing is stored` (`@bug:BUG-003`, PetStore_Pet.feature)

## Description

The spec (`swagger.json`) marks `name` as required and `status` as an enum (`available`, `pending`, `sold`),
and defines `405 Invalid input` for `POST /pet`. The API does not validate either rule: it answers `200`
and stores the invalid pet.

## Steps to reproduce

1. `POST /pet` with body `{"id": 918273001, "status": "available", "photoUrls": []}` (no `name`)
2. `POST /pet` with body `{"id": 918273002, "name": "Rex", "status": "flying", "photoUrls": []}`
3. `GET /pet/918273001` and `GET /pet/918273002`

## Expected

- Steps 1 and 2 are rejected with `405 Invalid input`, as the spec defines.
- Step 3 returns `404 Pet not found` for both: nothing invalid is stored.

## Actual

- Step 1 returns `200` with `{"id":918273001,"photoUrls":[],"tags":[],"status":"available"}`.
- Step 2 returns `200` with `{"id":918273002,"name":"Rex","photoUrls":[],"tags":[],"status":"flying"}`.
- Both pets are stored.

## Notes

The server already answers malformed JSON with `400 bad input`, so `400` may be the better code; the test
follows the published spec (`405`) until the spec is changed.

## Impact

Data that breaks the contract gets into the store and reaches every client that reads it.
